# RC_CAR 자율주행
- 해당 프로젝트는 RC_CAR 자율주행 5조 팀 프로젝트입니다.
- 가장 빠르고 안정적인 팀원의 RC_CAR로 진행했습니다.
- 그래도 모든 팀원이 자율주행에 성공을 했습니다.
- [5조 프로젝트 노션](https://www.notion.so/5-RC-CAR-29a402f9faac8018a66ac680cf6dfbfd)
- [개인 프로젝트 노션](https://www.notion.so/STM-RC-CAR-AUTO-MOBILITY-2a2253acced6802eb06dfb26025b5867)

## 구동 우선순위

1. 정면
    1. 정면 값이 50 이내에 들어오면 서서히 감속
    2. 정면 값이 35 이내에 들어오면 정지
    3. 좌우 비교를 통해 센서의 값이 높은 쪽으로 회전
    4. 정지할 때의 정면 값과 정지된 값 +a 보다 커지면 바로 직진
    5. 직진하더라도 카운터 조건을 추가해서 2번 정도는 확인
2. 좌우 비교
    1. 직진하더라도 중간을 따라 이동하는게 아니라 한쪽으로 치우쳐서 이동할 경우
    2. 좌우 값을 비교해서 해당 값의 차이가 20 이상 발생하면 높은 쪽으로 이동하여 중간으로 이동
3. 직진
    1. 위의 조건에 들어오지 않으면 무조건 직진

## 문제점 및 해결방안

1. 센서의 값이 너무 튀어서 정확한 값을 받지 못해 제자리에서 회전하는 문제점이 발생
    - 첫 번째: 트리거 센서를 한번에 호출하는게 아니라 index를 줘서 각각 실행하게 수정
        - 센서의 노이즈는 완벽하게 해결되었으나 약간의 딜레이 즉, 반응속도가 조금씩 느려짐
    - 두 번째: inputfilter 값을 높게 줘서 어느정도의 딜레이를 주어서 호출
        - 위에 방법보단 반응속도도 좋지만 완벽하게 해결하지는 못함
    - 세 번째: DMA값을 평균을 내서 중간에 높은 값을 받는다 하더라도 상쇄시키기
        - 센서의 튀는 값은 줄었으나 역시 100개의 데이터가 빠르게 값이 변하지는 않아서 반응속도가 다소 느려짐 그래서 10개의 값으로 처리를 했음
2. 구간에서 회전은 완벽하게 잘됨 하지만, 회전 이후 직진 시 좌우 값 계산을 정확히 못함
    - 이 문제는 여러 방안으로 시도했지만 해결이 안됨
    - 현재는 해결 완료 그냥 위에 문제들 때문에 같이 일어나는 현상 (반응속도)
3. 반응속도가 너무 느림
    - 트리거를 각각 받아오는게 아니라 각각의 센서 트리거호출 함수를 나눠서 동시에 실행되게 수정하고 튀는 센서 값은 10개의 데이터로 약간의 상쇄를 시켜서 즉각 반응은 아니지만 어느정도 값을 높게 줘서 한 틱 빠르게 작동하게 해결
